🛣️ Los 3 caminos entre Ram-Cehta y Nubox

Nubox se usa para cosas distintas y cada una tiene su propio camino. No se mezclan:

📤
A · Asientos contables (CSV)
Los vouchers aprobados/pagados se exportan en un archivo CSV que el contador importa en Nubox. Es el flujo contable mensual con MCG. Ya operativo — no necesita credenciales ni API.
📍 Administración → Exportación contable (/admin/nubox-exports)
🧾
B · API directa (factura y ventas)
Conexión automática con Nubox: emitir facturas electrónicas (DTE) desde un voucher, sincronizar las ventas del mes, y bajar PDF/XML firmados. Conectada en modo prueba para las 10 empresas.
📍 Estado visible en Administración → Estado del sistema
👥
C · Libro de remuneraciones
Lee el libro de remuneraciones del portal Nubox (usuario y clave del portal, no API). Experimental — camino aparte, con carga manual de Excel como respaldo.
📍 Administración → Nubox (/admin/nubox)
No confundir las pantallas: la página /admin/nubox es SOLO el libro de remuneraciones (camino C). El export contable vive en /admin/nubox-exports (camino A) y el estado de la API en /admin/sistema-status (camino B).

🧪 Ambiente de pruebas (UAT) vs Producción

Las credenciales que envió Nubox son de certificación (UAT): un ambiente de práctica con datos ficticios. Sirve para validar que todo funciona antes de tocar datos reales.

🔗 Prerequisito contable: mapear cuentas Cehta ↔ Nubox

Para que un asiento llegue a Nubox con la cuenta correcta, cada cuenta del plan de Ram-Cehta debe tener su código Nubox equivalente (campo "código Nubox" de la cuenta). La regla del fondo es que ambos planes sean espejo 1:1 con MCG.

  1. Andá a Contabilidad → Plan de cuentas.
  2. Verificá que las cuentas que usás en vouchers tengan su código Nubox cargado.
  3. Si falta alguno: se puede editar la cuenta individualmente, o re-importar el plan por Excel con la columna NuboxCode completa (el import actualiza sin duplicar).
  4. Si MCG crea una cuenta nueva en Nubox, se replica en Ram-Cehta dentro de 24h (invariante del fondo).
Qué pasa si falta el mapeo: el export NO se cae — usa el código interno de Cehta como respaldo. El riesgo es silencioso: si ese código no existe en Nubox, el asiento se rechaza o se imputa mal al importar en Nubox. Antes del primer export real, repasá el mapeo con MCG.
