# Audit CDN — Vercel · 2026-05-31

## TL;DR

✅ **Vercel CDN está configurado óptimamente**. No hay nada que cambiar.

## Métricas medidas

### Cache headers

| Recurso | Cache-Control | Resultado |
|---|---|---|
| `/_next/static/chunks/*.js` | `public, max-age=31536000, immutable` | ✅ 1 año, sin revalidación |
| `/_next/static/css/*.css` | `public, max-age=31536000, immutable` | ✅ 1 año, sin revalidación |
| HTML root (`/login`, etc) | `public, max-age=0, must-revalidate` | ✅ Siempre fresco |

### Vercel CDN edge

| Header | Valor | Interpretación |
|---|---|---|
| `X-Vercel-Cache` | `HIT` | Servido desde edge, no re-renderizado |
| `X-Vercel-Id` | `gru1::xxx` | Edge en São Paulo (cerca de Chile) |

### Compresión

| Encoding | Tamaño bytes | Ratio |
|---|---|---|
| identity (raw) | 4872 | 100% |
| gzip | 2498 | 51% (-49%) |
| brotli | 2668 | 55% (-45%) |

Vercel decide el algoritmo según el `Accept-Encoding` del browser. Para
JS chunks pequeños, gzip + brotli son similares.

## Conclusión

Sin cambios necesarios. Vercel maneja todo automáticamente:
- Cache-Control inmutable en chunks con hash en el nombre
- Edge CDN en São Paulo (latencia baja desde Chile)
- Compresión automática (gzip/brotli según browser)
- HTML root no cacheado (cambios reflejan instantáneo)

Este audit se repite cada 6 meses para asegurar que Vercel mantiene estos
defaults.
