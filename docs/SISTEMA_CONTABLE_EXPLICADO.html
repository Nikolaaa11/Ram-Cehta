01 · Arquitectura

Tres piezas. Cero acoplamiento.

El sistema vive en tres capas físicamente separadas. Cada una se puede reemplazar sin tocar las otras. Esto importa porque significa que si Vercel se cae mañana, el backend sigue funcionando; si Supabase migra, el frontend ni se entera.

Frontend

Next.js 15 + React

Lo que ves y tocás. 14 pantallas funcionales: vouchers, cartolas, reportes, plan de cuentas, áreas, proyectos, marcha blanca, admin.

Hospedado en Vercel con CDN global. Compilado a HTML estático cuando se puede (más rápido que cualquier SaaS comercial).

FastAPI + Python

El cerebro. 80+ endpoints REST que validan, autorizan, persisten y coordinan integraciones externas (SII, Nubox, Dropbox, email, IA).

Hospedado en Fly.io región São Paulo (gru). Auto-restart, health checks, cifrado Fernet para credenciales sensibles.

Base de datos

Supabase Postgres

La fuente de verdad. 40+ migraciones SQL. La regla de partida doble está escrita en triggers de Postgres — la última red de seguridad aunque el código aplicativo tenga un bug.

Row-level security activa por empresa. Backups automáticos diarios. Audit log inmutable.

02 · La unidad mínima

Todo es un voucher.

En tu sistema no existe "factura", "boleta", "transferencia" o "gasto" como cosas separadas. Existe el voucher: una transacción contable formal con líneas que debe cuadrar (partida doble). Todo lo demás son adornos.

La regla sagrada: partida doble

Cada peso que entra a una cuenta sale de otra. Suma de débitos = suma de créditos. Siempre. Si no cuadra, el sistema lo rechaza en 3 capas distintas:

  1. Zod (navegador) — rechaza antes de hacer la red call
  2. Pydantic (API) — rechaza antes de tocar la DB
  3. Trigger Postgres — rechaza incluso si los dos anteriores fallan

Es paranoico a propósito. Un fondo legal no puede permitirse asientos descuadrados en producción.

Vida del voucher

Un voucher recorre 7 estados. Solo puede avanzar — nunca retroceder. Esto es lo que hace el sistema auditable en el sentido legal del término: cada transición queda registrada con timestamp, usuario y motivo.

DRAFT→ PENDING→ APPROVED→ EXECUTED→ SYNCED→ RECONCILED→ CLOSED
DRAFT

Borrador

Estado libre. Acá podés descuadrar, dejar líneas incompletas, guardar y volver mañana. Es el único estado que permite errores temporales.

PENDING

En aprobación

El voucher ya cuadra. Está esperando 1 o 2 firmas (según monto). El usuario que lo creó no puede aprobar el suyo propio — separación de deberes obligatoria.

APPROVED

Aprobado

Tiene las firmas que necesita. Listo para ejecutarse, pero la plata todavía no se mueve. Útil para revisar la cola del día antes de pagar.

EXECUTED

Ejecutado

La transferencia bancaria salió. La plata ya no está en tu cuenta — está en la del proveedor. Se generó un movimiento bancario asociado.

SYNCED

Enviado a Nubox

El asiento ya está cargado en el sistema contable oficial (Nubox). MCG Consultores ya puede verlo en sus libros. Trazabilidad por folio Nubox.

RECONCILED

Conciliado

El cargo aparece en la cartola bancaria y coincide con el voucher. Match automático por monto + fecha + referencia. Sin sorpresas.

También existen 3 estados terminales fuera de la línea principal: REJECTED VOID REVERSO

"Cada línea de cada voucher imputa contra tres dimensiones: cuenta contable, proyecto (origen del costo), y área (centro de responsabilidad). Eso es lo que te permite armar un EEFF por proyecto sin tocar Excel." — Triple imputación · Invariante #4 del MAESTRO
03 · Operación diaria

Un día en el sistema.

Así se ve la jornada de quien opera Ram-Cehta. La diferencia con un sistema tradicional contable es que la IA hace el trabajo mecánico (clasificar emails, extraer datos de facturas, sugerir cuentas), y el humano hace solo el trabajo de criterio (aprobar, ajustar, autorizar pagos).

1

Mañana

Inbox IMAP trae facturas. Claude las clasifica y propone vouchers.

2

Mediodía

Operador revisa propuestas, completa datos, guarda en DRAFT.

3

Tarde

Manager aprueba (1ra firma). CFO aprueba (2da firma si > $1M).

4

Pago

Operador ejecuta transferencia desde caja chica o banco principal.

5

Conciliación

Cartola Dropbox + match automático. Marca RECONCILED.

6

Sync

CSV / API a Nubox. MCG Consultores lo ve al día siguiente.

Paso 1 — Inbox IA

Claude lee tus emails

Cada 10 minutos, el sistema revisa el buzón IMAP. Si entra una factura en PDF, Claude (Anthropic) lee el adjunto, extrae RUT, folio, monto neto, IVA, fecha, glosa, cuenta sugerida, y crea un voucher en estado DRAFT esperando aprobación humana.

Costo aproximado: $0,005 USD por factura procesada. A 100 facturas/mes son $0,50.

Paso 2 — Formularios

3 formularios distintos

No todo es una factura. El sistema tiene 3 entrypoints según el tipo de transacción:

/vouchers/nuevo — gasto/ingreso genérico
/vouchers/nubox — flujo idéntico al sistema Nubox
/vouchers/corfo — gastos con financiamiento CORFO marcado

Paso 3 — Aprobación

Doble firma según monto

Vouchers < $1M CLP: 1 firma de manager.
Vouchers ≥ $1M CLP: 1 firma manager + 1 firma CFO.
Vouchers ≥ $10M CLP: además requiere acta de comité de inversiones.

Segregación de deberes obligatoria: quien creó no puede aprobar.

Paso 4 — Pago

Transferencia trazable

No hay "nómina masiva" (decisión deliberada para fondos pequeños). Cada transferencia sale ordenada desde un voucher aprobado, con número de referencia que viaja al banco.

Comprobante bancario PDF se sube como adjunto del voucher (queda en Dropbox encadenado por hash).

Paso 5 — Conciliación

Match automático

Diariamente baja la cartola del banco desde Dropbox. El sistema busca por monto + fecha ± 2 días + referencia. Si el match es perfecto, marca RECONCILED automáticamente.

Si hay discrepancia, queda en cola humana para revisión.

Paso 6 — Nubox

El asiento oficial

Ram-Cehta es el sistema operativo del fondo, pero Nubox es donde MCG Consultores lleva la contabilidad legal. Cada voucher EXECUTED se exporta como CSV o se manda por la API REST oficial (cuando lleguen las credenciales de soporte@nubox.com).

Días 1 a 10. El ritmo del fondo.

Todo lo anterior es para que el cierre mensual sea trivial. En vez de tomar una semana de Excel-y-correcciones, el wizard de cierre te lleva del día 1 al 10 con checklist automático.

Saldo inicial vs saldo final. Cero diferencia.

D3

Conciliación bancaria

Toda cartola conciliada, sin pendientes.

D5

Sync Nubox

Todos los vouchers EXECUTED enviados.

D7

EEFF preliminar

Estado de Resultado + Balance generado.

D9

Revisión MCG

Contador externo valida.

D10

Cierre formal

Mes bloqueado. No se editan más vouchers.

"El día 11 ya no podés cambiar nada del mes anterior. Si encontrás un error después, se corrige con un voucher de ajuste con fecha del mes corriente. Esto es lo que un auditor externo espera ver." — Invariante #11 · Inmutabilidad post-cierre

06 · Seguridad y compliance

22 invariantes no negociables.

El sistema está diseñado para que sea técnicamente imposible romper las reglas legales, contables o tributarias. No "el sistema te avisa" — el sistema directamente no te deja hacerlo.

Legal · 5 reglas

FIP CEHTA ESG

Segregación por empresa con RLS. Audit log inmutable de cada cambio. Inmutabilidad post-cierre. Reverso por contra-asiento, nunca por delete. RUT validado siempre.

Contable · 8 reglas

Partida doble & cía.

Triple validación de partida doble. Triple imputación (cuenta + proyecto + área). Mes cerrado bloqueado. Plan de cuentas único por empresa. Saldos siempre derivados, nunca hardcoded.

Tributario · 4 reglas

SII chileno

COMPRA/VENTA exigen documento tributario válido. IVA tratamiento explícito por línea. Folio único por empresa-tipo-año. Conciliación con SII obligatoria pre-cierre.

Seguridad · 5 reglas

Datos sensibles

2FA obligatorio para admin. Cifrado Fernet de toda credencial externa. RBAC por rol (operador, manager, CFO, auditor). Sesiones JWT con expiración. PII redactada en logs.

07 · Alternativas de mejora

9 palancas para acelerar.

Cada una tiene un costo (en horas, plata o complejidad) y un beneficio. Las ordeno por impacto sobre tu día a día operativo, no por dificultad técnica.

Mejora #1 · Impacto ALTO

Transaction pooler en DB

Hoy el backend abre una conexión nueva a Supabase por cada request. Eso suma 80-200ms de latencia. Con pgbouncer transaction pooler (free en Supabase), las conexiones se reusan.

Ganancia esperada: 30-40% más rápido en endpoints de lectura.
Costo: 2 horas de configuración + testing.
Riesgo: bajo (cambio de string de conexión).

Mejora #2 · Impacto ALTO

Materialized views para EEFF

Los reportes financieros (Balance, Estado de Resultado, EEFF consolidado) hoy se calculan en vivo a partir de millones de líneas de voucher. Con una materialized view que se refresca cada 5 min, abren al instante.

Ganancia: reporte EEFF de 8s → 200ms.
Costo: 4-6 horas + migración SQL.
Riesgo: medio (cuidar staleness en cierre).

Mejora #3 · Impacto ALTO

IA extract más agresiva

Hoy Claude lee facturas y propone vouchers. La siguiente capa: que también lea contratos de proveedores y precargue plantillas mensuales recurrentes ("arriendo oficinas $X cada día 5"). Reduce drásticamente la captura manual.

Ganancia: ~40% menos tiempo en data entry.
Costo: 1-2 semanas de dev + tuning prompts.
Costo operación: +$5-15 USD/mes en Claude API.

Mejora #4 · Impacto MEDIO

Bulk operations en UI

Hoy aprobás vouchers de a uno. Para cierre mensual con 100+ vouchers eso es tedioso. Checkbox + "Aprobar 47 seleccionados" ahorra horas el día 8 del mes.

Ganancia: 2-3 horas/mes de cierre.
Costo: 1 día de dev en frontend.
Cuidado: mantener regla de doble firma por monto.

Mejora #5 · Impacto MEDIO

PWA + Push notifications

Que se instale en el celular como app nativa. Con notificaciones push cuando hay un voucher esperando tu aprobación, o cuando una conciliación falla. Hoy revisás manualmente el dashboard.

Ganancia: aprobaciones de 6 horas a 30 min de respuesta promedio.
Costo: 3-5 días de dev (service worker + Web Push).

Mejora #6 · Impacto MEDIO

Atajos de teclado

Para usuarios power (vos, contadora MCG): N nuevo voucher, A aprobar, / buscar, ⌘K paleta de comandos estilo Linear/Vercel.

Ganancia: productividad ~30% para usuarios diarios.
Costo: 2-3 días.

Mejora #7 · Impacto MEDIO

Anomaly detection IA

Que Claude analice cada noche el patrón histórico de gastos y marque desviaciones: "este proveedor cobra siempre $400k, hoy te facturó $4M", "esta cuenta tiene movimientos fuera de horario laboral", "doble pago detectado".

Ganancia: previene 80% de fraudes y errores grandes.
Costo: 1 semana dev + $3-8 USD/mes API.

Mejora #8 · Impacto BAJO

Dashboard ejecutivo

Pantalla única tipo Bloomberg: cash position consolidada, runway por empresa, burn rate, vouchers pendientes urgentes, NAV del fondo, retorno YTD. Para mostrarle a LPs sin compilar PDF.

Ganancia: reportería ad-hoc desaparece.
Costo: 1-2 semanas de dev + diseño.

Mejora #9 · Impacto BAJO

Webhook real-time

Hoy el polling IMAP corre cada 10 min. Si configuramos webhook de Resend + carpeta Dropbox watch, los eventos llegan en segundos en vez de minutos.

Ganancia: facturas aparecen al instante.
Costo: 2-3 días + endpoint público.

"La regla para priorizar: ¿qué te ahorra más tiempo el día 1-10 del mes? Eso siempre gana sobre lo que es técnicamente lindo pero solo se usa una vez al año." — Heurística de priorización operativa
